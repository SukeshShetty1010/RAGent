<data_audit>
  - HTML artifacts present in long-form text fields such as <description> and <description_raw>, including paragraph tags, line breaks, and encoded entities. These must be sanitized for downstream NLP and analytics.
  - Deeply nested arrays with mixed semantics:
    - <platforms> contains objects wrapping <platform>, <released_at>, and <requirements>.
    - <parent_platforms> is a higher-level abstraction that duplicates platform information with less granularity.
  - System requirements (<requirements.minimum>, <requirements.recommended>) are unstructured free-text blobs, inconsistent across platforms, and sometimes null.
  - Redundant identifiers and cosmetic fields detected:
    - <slug> largely duplicates <name> semantics.
    - Color/image-related fields (e.g., <background_image>, <dominant_color>) are non-analytical noise.
  - Ratings information is split across multiple representations:
    - Aggregate <rating> and <rating_top>.
    - Distributional <ratings> array.
    - Platform-specific <metacritic_platforms>.
  - Engagement counters (<added_by_status>, <reactions>) are dynamic, time-sensitive, and may introduce temporal noise if not normalized.
  - Tag objects (<tags>) include multilingual labels and highly granular user-generated concepts, increasing semantic noise without filtering.
  - Nullable or inconsistently typed fields observed (e.g., <esrb_rating> may be null, <metacritic> may be missing).
</data_audit>

<cleaning_strategy>
  1. Text Sanitization:
     - Strip all HTML tags from text fields (<description>, <description_raw>).
     - Decode HTML entities and normalize whitespace.
     - Preserve a single canonical long description field; drop raw/duplicate variants after cleaning.

  2. Identifier & Core Metadata Normalization:
     - Retain RAWG <id> as the primary source identifier.
     - Keep <name> as the canonical title; drop <slug> unless needed for URL generation.
     - Normalize <released> into ISO-8601 date and derive <release_year>.

  3. Platform Modeling:
     - Use <platforms> (not <parent_platforms>) as the authoritative source due to higher granularity.
     - Flatten into an array of platform objects with:
       - platform_name
       - platform_family (derived from parent_platforms if needed)
       - release_date_per_platform
       - raw_requirements_text

  4. Requirements Handling:
     - Preserve <requirements.minimum> and <requirements.recommended> as raw text fields.
     - Do NOT attempt full parsing at ingest time; instead:
       - Store raw text.
       - Optionally add a boolean flag <requirements_structurable> indicating whether regex-based parsing may succeed later.

  5. Ratings Strategy:
     - Retain aggregate rating fields (<rating>, <rating_top>, <metacritic>).
     - Preserve <ratings> distribution as a normalized array (title, percent, count).
     - Preserve <metacritic_platforms> as a separate array keyed by platform.

  6. Taxonomy Normalization (Genres, Developers, Publishers):
     - Flatten nested objects into string arrays using their <name> fields.
     - Deduplicate case-insensitively.

  7. Tags Filtering:
     - Retain tags but apply filtering rules:
       - Keep only tags with language = "eng".
       - Optionally drop tags below a relevance threshold (e.g., very low <games_count>).
     - Store tags as a lightweight array of strings.

  8. Engagement Metrics:
     - Retain <added_by_status> and <reactions> but isolate them under an <engagement> object.
     - Mark these fields as volatile (non-deterministic) for analytical caution.

  9. Null & Optional Fields:
     - Ensure all optional fields (e.g., <esrb_rating>) are nullable in schema.
     - Use empty arrays instead of nulls for list fields to simplify downstream processing.
</cleaning_strategy>

<target_schema>
  {
    "game_id": "Int",

    "description": "String",
    "release_date": "Date",
    "release_year": "Int",

    "platforms": [
      {
        "platform_name": "String",
        "platform_family": "String",
        "release_date": "Date",
        "requirements_minimum": "String",
        "requirements_recommended": "String"
      }
    ],

    "genres": ["String"],
    "developers": ["String"],
    "publishers": ["String"],

    "ratings": {
      "average_rating": "Float",
      "rating_top": "Int",
      "metacritic": "Int",
      "distribution": [
        {
          "label": "String",

        }
      ],
      "metacritic_by_platform": [

      "rawg_url": "String",
      "last_updated": "DateTime"
    }
  }
</target_schema>

<edge_case_handling>
  - If <platforms> is empty or null, fall back to <parent_platforms> to infer coarse platform availability.
  - If <requirements> text is missing for a platform, explicitly set requirements fields to null rather than empty strings.
  - If <metacritic> is missing but <metacritic_platforms> exists, compute no aggregate; keep platform scores only.
  - If multilingual tags are present without a language field, default to exclusion to reduce noise.
  - If <released> is missing, derive <release_year> from platform-specific release dates when possible.
</edge_case_handling>
