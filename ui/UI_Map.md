# PHASE 1 — UI CONTRACT
## Immutable Service Level Interface (SLI) for RAGent UI

**Status:** Canonical  
**Audience:** Frontend Engineers, Platform Engineers, QA  
**Scope:** Defines the immutable contract between the RAG Execution Engine and any UI (Web, Desktop, CLI).  
**Source of Truth:** `engine/execution_engine.py`, `tests/KPI_run.py`, `retriever/quality_gate.py`, `agent/task_router.py`

---

## 0. Core Principles

1. **Backend Owns Truth**
   - All metrics, classifications, confidence scores, and quality states are computed by the Engine.
   - The UI must never recompute, infer, or “fix” backend values.

2. **Fail-Soft Rendering**
   - The UI must render all available data even if parts of the execution failed.
   - Absence of data is not an error; it is a state.

3. **Deterministic Consumption**
   - The UI treats the response as an immutable snapshot.
   - No field mutation, aggregation, or derivation is allowed in the frontend.

---

## 1. Execution Contract — Data Schema

The Engine returns a single immutable object per request, referred to as **ExecutionResult**.

### 1.1 Top-Level Structure

| Field Name        | Type        | Nullable | Guarantee |
|------------------|-------------|----------|-----------|
| final_answer     | string      | No       | Always present. May be empty or contain a fallback message. |
| agent_decisions  | object      | No       | Always present. Describes routing, retrieval, and quality decisions. |
| evidence         | array       | No       | Always present. May be empty if no usable context exists. |
| kpis             | object      | No       | Always present. Contains per-request KPIs only. |
| raw_metrics      | object      | No       | Always present. Full observability snapshot. |

---

### 1.2 `final_answer`

**Semantic Meaning:**  
The best possible answer generated by the system under current conditions.

**Guarantees:**
- Always a string.
- Never null.
- May contain:
  - A fully generated answer.
  - A partial answer.
  - A fail-soft fallback message if LLM execution failed.

**UI Rule:**  
The UI must display this verbatim. No post-processing, trimming, or summarization is allowed.

---

### 1.3 `agent_decisions`

**Semantic Meaning:**  
A transparent explanation of *why* the Engine behaved the way it did.

**Guaranteed Subfields:**

| Subfield | Meaning |
|--------|---------|
| task | Task type selected by the router (`comparison`, `listicle`, `factual`, `open`). |
| routing_reason | Human-readable explanation of task selection. |
| retrieval_strategy | Concrete retrieval configuration used. |
| merge_state | Final context merge state (`LOCAL_ONLY`, `LOCAL_PLUS_WEB`, etc.). |
| quality | Quality assessment emitted by the Quality Gate. |

**UI Rule:**  
This object is informational only. It must never influence UI logic or branching.

---

### 1.4 `evidence`

**Semantic Meaning:**  
The final, filtered context provided to the LLM.

**Structure:**  
Array of evidence objects containing content, source metadata, and scores.

**Guarantees:**
- Ordered by relevance.
- Already deduplicated and noise-filtered.
- Safe to display as-is.

**UI Rule:**  
The UI must not re-rank, filter, or collapse evidence.

---

### 1.5 `kpis`

**Semantic Meaning:**  
Per-request performance and outcome indicators.

**Guaranteed Fields:**

| KPI Field | Meaning |
|---------|---------|
| engine_latency_ms | End-to-end request latency. |
| llm_ran | Boolean indicating whether the LLM was invoked. |
| llm_latency_ms | Nullable latency of LLM call. |
| quality_status | One of `quality_ok`, `quality_weak`, `quality_empty`. |
| confidence_score | Confidence score emitted by the Quality Gate. |
| retrieved_chunks | Number of chunks used after filtering. |
| task_success | Boolean success indicator for this request. |

**UI Rule:**  
KPIs are display-only. Percentiles, deltas, or trends must never be computed in the UI.

---

### 1.6 `raw_metrics`

**Semantic Meaning:**  
Full observability snapshot from the Metrics Registry.

**Characteristics:**
- Contains counters, distributions, and categoricals.
- Intended for debugging, profiling, and internal inspection.

**UI Rule:**  
Raw metrics must never be shown by default.

## 2. UI Visibility Tiers

### Tier Definitions

- 🔵 **Tier 1 (Core User Experience)**  
  Essential user-facing information.

- 🟡 **Tier 2 (Debug / Inspector)**  
  Advanced diagnostics for power users or developers.

- 🔴 **Tier 3 (Forbidden)**  
  Internal data that must never be rendered.

### Tier Assignment

| Field | Tier |
|-----|------|
| final_answer | 🔵 |
| evidence | 🔵 |
| kpis.engine_latency_ms | 🔵 |
| kpis.quality_status | 🔵 |
| kpis.confidence_score | 🔵 |
| agent_decisions | 🟡 |
| raw_metrics | 🟡 |
| cache internals / keys | 🔴 |
| metric registries | 🔴 |

## 3. Panel Responsibility Matrix

### UI Components and Contracts

| Panel Name | Inputs | Responsibilities | Invariants |
|-----------|--------|------------------|------------|
| Answer Card | final_answer | Render the answer verbatim. | Must not modify text. |
| Evidence Panel | evidence | Display supporting context and sources. | No re-ranking or filtering. |
| KPI Ribbon | kpis | Display latency, quality, confidence. | No calculations or aggregation. |
| Trace Inspector | agent_decisions, raw_metrics | Show execution trace and metrics. | Read-only, opt-in only. |

## 4. Failure Semantics & UI Behavior

### 4.1 Quality States

Derived from `quality_gate.py`.

| QualityStatus | UI Mandate |
|--------------|------------|
| QUALITY_OK | Normal rendering. |
| QUALITY_WEAK | Render answer with visual warning indicator. |
| QUALITY_EMPTY | Render fallback answer and emphasize lack of evidence. |

---

### 4.2 LLM Failure

**Condition:**  
`llm_ran = false` or fallback text in `final_answer`.

**UI Behavior:**
- Display fallback answer.
- Continue to display evidence and KPIs.
- Never show an error modal.

---

### 4.3 Partial Success

**Condition:**  
Some stages succeeded while others failed.

**UI Behavior:**
- Render all available Tier 1 data.
- Annotate degraded states visually, not programmatically.
- Never block rendering due to missing fields.

---

## 5. Non-Negotiable UI Constraints

1. The UI must not infer task type, quality, or success.
2. The UI must not compute percentiles, averages, or trends.
3. The UI must not suppress backend-provided failure messages.
4. The UI must treat missing data as an explicit state, not an error.

---

This document is **immutable for PHASE 1**.
