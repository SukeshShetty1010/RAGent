OVERVIEW
--------
RAG_ent ingests game data from RAWG, IGDB, and GameSpot, normalizes and enriches it, stores canonical game objects plus chunked content in a Weaviate vector DB, and serves a Retrieval-Augmented Generation (RAG) pipeline that queries the vector DB and calls a hosted LLM (Modal) to produce answers.

Top-level flow (high level)
1. auth/ → pulls raw JSON responses from RAWG, IGDB, GameSpot
2. data/ → parses and normalizes raw JSON into structured records
3. ingest/loader.py → prepares per-source canonical objects + content docs
4. ingest/merge.py → merges per-source canonicals into single canonical (deterministic ID)
5. ingest/chunking.py → splits long text into chunks (chunk docs)
6. ingest/upsert.py → embeds and upserts canonical + chunk objects to Weaviate (native batch)
7. vector/index_manager.py → creates/updates Weaviate class schema
8. retriever/retriever.py & retriever/rag.py → runs semantic search and prompts LLM
9. llm/ → calls Modal LLM for generation
10. tests/ → unit & integration tests (ingest, schema, retrieval)

DETAILED MODULE RESPONSIBILITIES
-------------------------------
auth/
  - rawg_client.py, igdb_client.py, gamespot_client.py
  - Responsibilities:
    * Centralize API requests, pagination, rate-limit handling, retries.
    * Return parsed JSON for downstream `data/` wrappers.

data/
  - rawg_data.py, igdb_data.py, gamespot_data.py, helper.py
  - Responsibilities:
    * Convert source API JSON to canonical source-structured JSON (fields are not final canonical)
    * Provide helper utilities (slugify, normalize lists, canonicalize platforms, to_int_or_none)
    * Pre-validate fields required for merging (title, release_date, id, site_url)

ingest/
  - loader.py
    * Input: source structured JSON (file or dict)
    * Output:
      - per-source canonical dicts (plain JSON-serializable; includes `raw_source_blob` string)
      - content docs (list of {"text": "...", "metadata": {...}}) ready for chunking
    * Key behaviours:
      - Deterministic `unified_game_id` generation (slug + year + 8hex)
      - Normalize arrays → List[str]
      - Cast `game_id` to int or None
      - Filter GameSpot reviews/articles by game association (game id or slug in URL)
      - Remove `raw_source_blob` from chunk metadata
  - merge.py
    * Input: list of per-source canonicals for same game
    * Output: merged canonical dict (doc_type="canonical")
    * Key behaviours:
      - Deterministic canonical ID (unified_game_id)
      - Merge arrays (dedupe, preserve first-seen case)
      - Choose scalar fields by source precedence (gamespot > igdb > rawg)
      - Aggregate ratings to score_normalized & score_count
      - Collect `raw_source_blob` map {source: raw_json_string} and store as a single JSON string on canonical
      - Deduplicate Releases/Articles/Reviews where present
  - chunking.py
    * Input: content docs (text + metadata)
    * Output: chunk docs (text + metadata) with:
      - doc_type = "chunk"
      - chunk_type (description/review/article/release)
      - chunk_uuid (8 hex)
      - parent_unified_id
      - content_length and content_hash
    * Key behaviours:
      - Word-based splitting with overlap; min_words merging to avoid tiny fragments
      - Keep language="en"
  - upsert.py
    * Native Weaviate batch upsert (no LangChain add_documents)
    * Use `unified_game_id` as canonical object UUID
    * Use `unified_game_id__chunk__<chunk_uuid>` as chunk UUIDs
    * Compute content_hash (sha256) and dedupe on that if desired
    * Preserve arrays as native lists for TEXT_ARRAY schema fields
    * Embed canonical (description) and each chunk text using HuggingFace all-MiniLM-L6-v2 (CPU)

vector/
  - embed.py
    * Exposes `get_embedding_model()` wrapper
    * Batch embedding helpers and fallbacks for different embedder APIs
  - index_manager.py
    * Creates `GameKnowledge` class in Weaviate (TEXT_ARRAY fields for lists)
    * Ensures numeric fields are typed correctly (release_year: Int, game_id: Int (nullable))
    * Exposes `client` and `COLLECTION_NAME`
  - search.py
    * Vector search helper used by retriever (k-NN, filter by metadata)

retriever/
  - retriever.py
    * Query Weaviate for top-k chunks given an embedding or text query
    * Apply metadata filters (e.g., platform, release_year)
  - rag.py
    * Compose prompt with retrieved context (canonical + top chunks)
    * Calls `llm/ragent_client.py` to get generated answer
    * Return answer + sources list (canonical IDs + chunk ids)

llm/
  - modal_llm.py
    * Modal deployment code (Llama-3)
  - ragent_client.py
    * Client wrapper to call deployed LLM service (handle API signature changes)

tests/
  - test_ingestion_enrichment.py
    * Validates schema conformity, arrays as lists, date RFC3339 compliance
  - test_rag_retrieve.py
    * End-to-end retrieval test using stub LLM or Modal test endpoint
  - test_{rawg,igdb,gamespot}_modules.py
    * Unit tests for parsing/normalization

KEY STRUCTURES / SCHEMAS

{
  "unified_game_id": "far-cry-3-2012-91c94846",  # deterministic slug-year-hash
  "doc_type": "canonical",
  "slug": "far-cry-3-2012",
  "title": "Far Cry 3",
  "description": "Long description text ...",
  "release_date": "2012-11-29T00:00:00Z",
  "release_year": 2012,                      # Int (nullable)
  "game_id": 12345,                          # Int (nullable)
  "genres": ["Action", "Shooter"],           # List[str]
  "platforms": ["PC", "PS4"],                # List[str]
  "developers": ["Ubisoft"],                 # List[str]
  "publishers": ["Ubisoft"],                 # List[str]
  "score_normalized": 86.5,                  # Float (0–100)
  "score_count": 3,                          # Int
  "raw_source_blob": "{\"rawg\": \"{...}\", \"gamespot\": \"{...}\"}",  # JSON string
  "merge_time": "2025-11-12T12:00:00Z",
  "created_at": "2025-11-01T12:00:00Z"
}

Chunk object — JSON (example)
{
  "doc_type": "chunk",
  "chunk_type": "review",                # description/review/article/release
  "chunk_uuid": "9f1a2b3c",              # 8 hex
  "parent_unified_id": "far-cry-3-2012-9f1a2b3c",
  "text": "Review: This game ...",
  "metadata": {
    "source": "gamespot",
    "source_game_id": "515516",
    "game_id": 515516,
    "unified_game_id": "far-cry-3-2012-9f1a2b3c",
    "slug": "far-cry-3-2012",
    "title": "Far Cry 3",
    "chunk_type": "review",
    "review_id": 1234,
    "content_length": 312,                # word count
    "content_hash": "sha256-hex",
    "language": "en"
  }
}

WEAVIATE SCHEMA MAPPING (recommended)
------------------------------------
Class name: GameKnowledge (COLLECTION_NAME)
- unified_game_id: text (keyword) — also used as object UUID
- doc_type: text
- slug: text (indexable)
- title: text
- description: text
- release_date: date (RFC3339)
- release_year: int
- game_id: int (nullable)
- genres: text[] (TEXT_ARRAY)
- platforms: text[] (TEXT_ARRAY)
- developers: text[] (TEXT_ARRAY)
- publishers: text[] (TEXT_ARRAY)
- score_normalized: number
- score_count: int
- raw_source_blob: text (long)   # store as string on canonical only
- content_length: int            # chunk property
- content_hash: text             # chunk property
- chunk_type: text
- chunk_uuid: text (indexed)
- vector:        vector datatype handled by Weaviate

DETERMINISTIC ID & HASHING RULES
--------------------------------
- canonical unified_game_id:
  slug = slugify(title) + "-" + Year
  unified_game_id = f"{slug}-{year}-{sha1(slug + '-' + str(year))[:8]}"
- chunk_uuid:
  make_hash8(f"{unified_game_id}__chunk__{index}") → first 8 hex
- Use canonical unified_game_id as Weaviate object UUID (ensures idempotency)
- Use chunk id = f"{unified_game_id}__chunk__{chunk_uuid}" as chunk UUID.

EMBEDDING & CHUNKING PARAMETERS
-------------------------------
- Embedding model: HuggingFace all-MiniLM-L6-v2
- chunk_size: ~800 words (or tune to ~3–4k tokens on MiniLM)
- chunk_overlap: 100 words
- min_words: 30 (merge tiny fragments)
- batch_size for embedding: 64
- store canonical vector = embedding(description or title)

UPSERT / DEDUP BEHAVIOUR
-----------------------
- Use native Weaviate batch insertion (collection.batch) to preserve text arrays.
- Before inserting chunk objects:
  - Compute content_hash (sha256 of normalized text)
  - Optionally check existing objects by content_hash to avoid re-inserting duplicates
- Upsert logic:
  1. Upsert canonical object with unified_game_id as UUID and canonical vector
  2. Upsert chunk objects keyed by chunk UUID; set vector if embedding available
  3. Optionally create cross references (if desired) via properties rather than edges

TESTS & VALIDATION CHECKLIST
----------------------------
Pre-upsert validator (run locally on merged JSONs):
- [ ] merged_canonical.json has unified_game_id and raw_source_blob as JSON string
- [ ] all_docs.json contains plain dicts with "text" and metadata (no Document objects)
- [ ] game_id fields are int or null
- [ ] arrays are native lists, not JSON-encoded strings
- [ ] chunk metadata contains chunk_type, chunk_uuid, content_hash
- [ ] No duplicates for releases/articles/reviews (dedupe by id)
- [ ] merge_time exists on canonical

Post-upsert checks (rough_verify_data.py)
- Confirm canonical object exists when fetched by unified_game_id
- Confirm arrays stored as arrays in Weaviate
- Confirm raw_source_blob exists on canonical and not on chunks
- Confirm vectors are present on objects if embeddings were written

DEBUGGING TIPS
--------------
- If you see arrays serialized as strings in Weaviate: ensure you're using native batch insert and supplying native Python lists to the properties (don't use LangChain's add_documents).
- If reviews appear unrelated to the canonical: check gamespot_data.py filter heuristics; ensure extract_game_id_from_item() finds the correct relation.
- If canonical_id collisions occur: check slugify and release_year parsing; ensure hash input string is deterministic.
- Use `dry_run=True` in upsert to inspect payloads before they hit Weaviate.
